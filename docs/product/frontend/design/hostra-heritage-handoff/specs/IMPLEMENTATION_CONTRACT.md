## Non-negotiable invariants
- UI redesign cannot change existing route guards, API types, backend authority, event state machine or role capability. Never make a hidden button the only security check. One workspace main per Owner and one concurrent LIVE MVP. Owner-only Start and approvals; assigned Operator runtime only as existing grants allow, including emergency stop without waiting for Owner. Multiple Operators may be assigned to the same session. Viewer and Rights Subject are distinct roles.
- Independent gates: presenter consent/image, preset voice rights, QC, OCOP, food compliance, knowledge/facts/claims, approved story revision, readiness and media. OCOP VERIFIED != knowledge APPROVED != READY. A new approved asset does not silently change a session snapshot. Source data/evidence and blocked claims cannot be fabricated.
- Commands REQUESTED/ACCEPTED are not APPLIED. LIVE only after media confirmation; Pause AI keeps stream running; Active SKU changes only after authoritative APPLIED. Pending commands, stale data and conflicts must be rendered truthfully. Emergency Stop has fast single confirmation; no new hold requirement. No direct state writes from display component.
- Private LiveKit MVP; no fake TikTok/Shopee, checkout, GMV, voice cloning, viewer replay, or public viewer URL inferred from localhost. QR encodes exactly real invite URL. Static preview screenshots use placeholder art; do not change media adapters.
- All sample data/metrics in mockup are examples. Actual backend data overrides mockup labels/numbers. For demo keep existing fixture data and mark simulation correctly. No new backend services just to match mockup visuals.

## States to preserve and test even if no separate screenshot
Every list: loading/skeleton, empty, filter no-results, error+retry, stale; every form: invalid, dirty draft, saving, failure, success; auth: forbidden, expired invite, no assigned session, revoked; Presenter: rights pending/revoked/expired, generation failure/retry, partial QC; catalog: pending review/rejected/expired/revoked; knowledge: missing evidence/blocked/stale revision; Story: conflict, pending review, approved; readiness: pending/blocked/ready/starting; Control: live/paused/degraded/failed/reconnecting, command requested/accepted/applied/rejected/timeout/conflict, stop/emergency; Viewer: waiting, invalid/expired/revoked/exhausted, buffering, chat sending/failure, reconnecting, ended; invites: exhausted/expired/revoked; Reports: N/A/partial/failed export. Existing state logic wins. Do not hide failures by styling.
